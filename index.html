🔬 So Sánh Chuyên Sâu: COUNT(*) vs COUNT(o.order_id)
Quy tắc chuẩn hóa SQL

Khi thực hiện LEFT JOIN, đối với khách hàng chưa từng mua hàng (như Charlie), bảng kết hợp tạm thời của MySQL sẽ sinh ra một dòng dữ liệu dạng:

Row: ( customer_id: 3, name: 'Charlie', order_id: NULL, product_id: NULL )

❌ Tại sao COUNT(*) gây sai lệch?

Hàm COUNT(*) đếm tổng số hàng vật lý được tạo ra trong nhóm sau khi GROUP BY. Vì dòng của Charlie vẫn tồn tại (dù các trường bên Orders là NULL), COUNT(*) sẽ đếm hàng này và cho ra kết quả 1 đơn hàng. Điều này làm hỏng toàn bộ logic phát voucher cho người chưa mua!

✅ Tại sao COUNT(o.order_id) chính xác tuyệt đối?

Theo đặc tả chuẩn ANSI SQL, hàm COUNT(tên_cột) tự động bỏ qua các giá trị mang giá trị NULL. Vì o.order_id của Charlie là NULL, hàm sẽ không tính nó và trả về chính xác số lượng đơn hàng là 0.

Câu 1: Phân biệt INNER JOIN và LEFT JOIN. Nếu đổi thành RIGHT JOIN và giữ nguyên thứ tự bảng thì sao? ▾

1. Sự khác biệt theo lý thuyết tập hợp:

  • INNER JOIN: Là phép giao tập hợp ($A \cap B$). Chỉ giữ lại các bản ghi có dữ liệu khớp ở cả hai bảng. Loại bỏ thẳng tay các bản ghi mồ côi.
  • LEFT JOIN: Giữ nguyên 100% bản ghi của bảng bên trái (Driving Table). Nếu bảng bên phải không có dữ liệu tương ứng, các trường của bảng phải sẽ được điền NULL.

2. Hậu quả khi viết Customers RIGHT JOIN Orders:

Lúc này bảng Orders trở thành Driving Table. Phép nối sẽ chỉ giữ lại những khách hàng nào có mã customer_id xuất hiện trong Orders. Kết quả là khách hàng Charlie tiếp tục bị biến mất hệt như khi dùng INNER JOIN, chiến dịch Marketing tiếp tục thất bại!

Câu 2: Tại sao điều kiện WHERE o.order_id IS NULL bắt buộc phải đi kèm LEFT JOIN? ▾

Bản chất của kỹ thuật Anti-Join là tìm các bản ghi thuộc bảng A nhưng không hề xuất hiện trong bảng B ($A \setminus B$).

Chỉ có LEFT JOIN mới sản sinh ra giá trị NULL cho các cột của bảng B đối với những dòng không tìm thấy liên kết.

Nếu dùng INNER JOIN, mọi dòng trong kết quả đều bắt buộc phải có giá trị hợp lệ (khác NULL). Do đó, điều kiện WHERE o.order_id IS NULL trở thành một mệnh đề mâu thuẫn tuyệt đối (Contradiction) và luôn trả về tập rỗng (0 dòng)!

Câu 3: Cross Join (Tích Descartes) là gì và khi nào một câu lệnh vô tình biến thành Cross Join gây treo máy chủ? ▾

1. Định nghĩa: Cross Join kết hợp từng dòng của bảng A với mọi dòng của bảng B, sinh ra tập kết quả có kích thước $M \times N$ dòng.

2. Các trường hợp vô tình biến thành Cross Join:

  • Viết SELECT * FROM Customers c JOIN Orders o; mà quên mệnh đề ON. Trong chuẩn SQL, JOIN không có ON sẽ tự động suy biến thành CROSS JOIN.
  • Dùng cú pháp cũ FROM Customers c, Orders o mà quên điều kiện WHERE nối khóa.
  • Viết điều kiện nối sai logic: ON 1=1 hoặc ON c.customer_id = c.customer_id (tự so sánh với chính nó).

3. Mức độ nguy hại: Nếu bảng khách hàng có 1 triệu dòng và đơn hàng có 10 triệu dòng, tích Descartes sẽ sinh ra 10 nghìn tỷ dòng ($10^{13}$), làm tràn RAM, đầy đĩa cứng tạm thời và làm treo toàn bộ máy chủ MySQL Production!

-- -----------------------------------------------------
-- HỆ THỐNG FLASHMART: GIẢI PHÁP TỐI ƯU HÓA TRUY VẤN JOIN
-- -----------------------------------------------------
DROP DATABASE IF EXISTS flashmart_db;
CREATE DATABASE flashmart_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
USE flashmart_db;

-- 1. Bảng Dữ Liệu
CREATE TABLE Customers (customer_id INT PRIMARY KEY, name VARCHAR(50) NOT NULL);
CREATE TABLE Products (product_id INT PRIMARY KEY, product_name VARCHAR(50) NOT NULL);
CREATE TABLE Orders (
    order_id INT PRIMARY KEY, 
    customer_id INT NOT NULL, 
    product_id INT NOT NULL,
    CONSTRAINT FK_Orders_Customers FOREIGN KEY (customer_id) REFERENCES Customers(customer_id),
    CONSTRAINT FK_Orders_Products FOREIGN KEY (product_id) REFERENCES Products(product_id)
);

-- 2. Dữ liệu mẫu
INSERT INTO Customers VALUES (1, 'Alice'), (2, 'Bob'), (3, 'Charlie');
INSERT INTO Products VALUES (101, 'Laptop'), (102, 'Mouse'), (103, 'Keyboard');
INSERT INTO Orders VALUES (1001, 1, 101), (1002, 1, 102), (1003, 2, 101);

-- 3. Báo cáo Marketing: Tối ưu với LEFT JOIN + COUNT(o.order_id)
SELECT 
    c.customer_id, 
    c.name, 
    COUNT(o.order_id) AS total_orders,
    CASE 
        WHEN COUNT(o.order_id) = 0 THEN 'Tặng Voucher 50% (Khách hàng tiềm năng)'
        ELSE 'Khách hàng thân thiết'
    END AS marketing_action
FROM Customers c
LEFT JOIN Orders o ON c.customer_id = o.customer_id
GROUP BY c.customer_id, c.name
ORDER BY c.customer_id ASC;

-- 4. Báo cáo Kho vận: Kỹ thuật Anti-Join (LEFT JOIN ... WHERE o.order_id IS NULL)
SELECT 
    p.product_id, 
    p.product_name,
    'Chưa từng phát sinh giao dịch - Đề xuất thanh lý' AS inventory_status
FROM Products p
LEFT JOIN Orders o ON p.product_id = o.product_id
WHERE o.order_id IS NULL;
